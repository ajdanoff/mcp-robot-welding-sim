# Архитектура модулей и математические алгоритмы (`mcp-robot-welding-sim`)

Документ описывает внутреннее устройство прототипа: от высокоуровневых контрактов Model Context Protocol (MCP) до вычислительного ядра кинематики манипулятора и GPU-ускорения пространственного поиска.

---

## 1. `kinematics.py` — Прямая и обратная кинематика 6-DoF манипулятора

Модуль реализует кинематическую модель 6-осевого промышленного сварочного робота (компоновка со сферическим запястьем, аналогичная KUKA / Mitsubishi).

### Основные методы и алгоритмы

* **`_dh_transform` и `forward_kinematics_chain` (Прямая кинематика, FK):**
  * **Алгоритм:** последовательное перемножение матриц однородных преобразований группы $SE(3)$ размерности $4 \times 4$ по стандартной параметризации **Денавита — Хартенберга (DH)** ($a_i, \alpha_i, d_i, \theta_i$).
  * **Результат:** возвращает цепочку систем координат от основания робота до кончика сварочной горелки (TCP), необходимую для последующей проверки коллизий каждого звена.

* **`compute_jacobian` (Аналитический геометрический якобиан):**
  * **Алгоритм:** прямое геометрическое построение матрицы $J \in \mathbb{R}^{6 \times 6}$ в базовой системе координат без численного дифференцирования. Для каждого вращательного сустава $i$:
    * Линейная составляющая скорости: $J_{v,i} = z_i \times (p_{\text{tcp}} - p_i)$
    * Угловая составляющая скорости: $J_{\omega,i} = z_i$
  * **Преимущество:** точность машинного эпсилон и отсутствие накладных расходов на 6 дополнительных вызовов FK на каждой итерации.

* **`_rotation_error` и `make_tool_orientation` (Геометрия на многообразии $SO(3)$):**
  * **Алгоритм:** построение правого ортонормированного базиса инструмента по заданной нормали шва через векторное произведение (`make_tool_orientation`) и вычисление ошибки ориентации через логарифмическое отображение группы вращений $SO(3) \to \mathfrak{so}(3)$ (вектор Эйлера / ось-угол из следа и кососимметрической части матрицы $R_{\text{err}} = R_{\text{target}} R_{\text{cur}}^T$).

* **`inverse_kinematics` (Обратная кинематика, IK):**
  * **Алгоритм:** **Damped Least Squares (метод Левенберга — Марквардта)** с мультистартом (`multi-seed search`) и ограничением шага $\Delta q$:
    $$\Delta q = (J^T J + \lambda I)^{-1} J^T e$$
  * **Защита от сингулярностей и скачков:** параметр демпфирования $\lambda = 10^{-4}$ стабилизирует обращение матрицы вблизи сингулярностей запястья; среди всех сошедшихся конфигураций выбирается решение с минимальной нормой скачка в пространстве обобщённых координат $\max_i |q_i - q_{\text{init}, i}|$.

## 2. `scene.py` — Геометрия рабочей сцены и детекция коллизий

Модуль описывает рабочее пространство ячейки, CAD-ограничения и физическую безопасность движения звеньев.

### Основные методы и алгоритмы

* **`WeldSeam` и `AABB` (Моделирование ограничений):**
  * **Алгоритм:** валидация геометрии швов и ограничивающих параллелепипедов (**Axis-Aligned Bounding Boxes**) с настраиваемым защитным допуском (`collision_margin_mm`) на уровне инициализации (Pydantic v2 / frozen dataclasses).

* **`check_chain_collision` (Дискретная проверка пересечений кинематической цепи):**
  * **Алгоритм:** линейная интерполяция отрезков между соседними системами координат суставов ($P(\alpha) = (1 - \alpha) P_{i-1} + \alpha P_i$, $\alpha \in [0, 1]$) с проверкой попадания каждой контрольной точки в расширенные объёмы препятствий (`Welding_Table`, `Workpiece_Core_Body`). Для кончика горелки (TCP) в точке сварки защитный отступ обнуляется для обеспечения контакта со швом.

## 3. `postprocessor.py` — Транслятор управляющих программ

Модуль отделяет геометрическое планирование от синтаксиса конкретного промышленного контроллера.

### Основные методы и алгоритмы

* **`TrajectoryWaypoint` (Промежуточное представление траектории):**
  * Типизированное представление опорной точки с типом интерполяции (`MOVJ` — суставное перемещение, `MOVL` — линейная интерполяция TCP), целевой скоростью и состоянием сварочного источника (`ARC_ON` / `ARC_OFF`).

* **`compile_program` (`_compile_melfa` / `_compile_gcode`):**
  * **Алгоритм:** двухпроходная кодогенерация. На первом проходе формируется таблица позиций инструмента (`P1..Pn`), на втором — последовательность команд движения, задержек стабилизации дуги (`DLY`) и управления дискретными выходами сварочного инвертора (`HOPEN 1` / `HCLOSE 1` для MELFA-BASIC или `M03` / `M05` для ISO G-code).

## 4. `mcp_server.py` — Сервер Model Context Protocol и конвейер валидации

Модуль реализует интерфейс взаимодействия AI-агента с симулятором на базе **MCP SDK v2 (`MCPServer`)**.

### Основные методы и алгоритмы

* **`get_workpiece_seams_resource` (`scene://workpiece/seams`) и `inspect_workpiece`:**
  * Предоставляют LLM структурированный контекст CAD-детали и метаданные доступных сварных швов.

* **`plan_and_simulate_weld` (Детерминированный Quality Gate):**
  * **Алгоритм:** строит безопасный профиль траектории `HOME -> APPROACH -> START (ARC_ON) -> MID -> END (ARC_OFF) -> RETRACT -> HOME`, затем последовательно применяет 3 уровня верификации:
    1. Проверка кинематической достижимости (`IK`) в опорных точках.
    2. Проверка непрерывности в пространстве суставов (`MAX_JOINT_JUMP_DEGREES = 120°`) для исключения резких переворотов запястья.
    3. Плотная дискретизация линейного сварного шва (`WELD_PATH_COLLISION_SAMPLES = 20`) с проверкой коллизий в каждой промежуточной точке.

* **`export_robot_program`:**
  * Блокирует генерацию управляющего кода при отсутствии валидированного плана в буфере и вызывает постпроцессор только для подтверждённых безопасных траекторий.

## 5. `notebooks/cuda_morton_broadphase_benchmark.ipynb` — GPU-ускорение пространственного поиска

Экспериментальный вычислительный модуль для масштабирования детекции коллизий (Broad-Phase) на сложные CAD-модели из сотен тысяч примитивов.

### Основные методы и алгоритмы

* **`compute_morton_kernel` (30-битное пространственное кодирование Мортона на CUDA):**
  * **Алгоритм:** отображение нормализованных 3D-координат в одномерную кривую Лебега (**Z-order curve**) через побитовый интерливинг (`magic bits` сдвиги и маскирование 10-битных координат в 30-битный ключ `uint32`).
  * **Оптимизация GPU:** хранение координат в формате **Structure of Arrays (SoA)** для коалесцированного доступа к глобальной памяти (`coalesced memory access`) и `grid-stride loop`.
  * **Производительность (NVIDIA T4, $10^6$ примитивов):** `0.201 мс` на GPU против `37.23 мс` на CPU NumPy (**ускорение в 185.2 раза** при 100% побитовом совпадении).
