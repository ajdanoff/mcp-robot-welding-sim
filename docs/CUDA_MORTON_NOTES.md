# Разбор реализации GPU / CUDA Spatial Indexing (`cuda_morton_broadphase_benchmark.ipynb`)

Документ содержит инженерное обоснование архитектурных решений в CUDA-ядре расчёта 30-битных кодов Мортона (Z-order кривой) для ускорения проверки коллизий (Broad-Phase Collision Detection) в 3D-симуляторе.

---

## 1. Раскладка памяти Structure of Arrays (SoA) и `__restrict__`

```cuda
__global__ void compute_morton_kernel(
    const float* __restrict__ xs,
    const float* __restrict__ ys,
    const float* __restrict__ zs,
    uint32_t* __restrict__ out_codes,
    uint32_t count
)
```

* **Коалесцированный доступ к памяти (Memory Coalescing):** Координаты \(1\,000\,000\) примитивов передаются в виде трёх отдельных непрерывных массивов (`xs`, `ys`, `zs`), а не массива структур `struct Point { float x, y, z; }` (Array of Structures, AoS). Когда 32 потока одного варпа (warp) одновременно обращаются к соседним элементам `xs[i]`, контроллер памяти GPU объединяет их запросы в единую 128-байтную транзакцию в кэш-линию L1/L2. При классическом AoS потоки читали бы данные с шагом 12 байт (stride), теряя пропускную способность шины памяти.
* **Оптимизация `__restrict__`:** Указывает компилятору `nvcc`, что входные и выходные указатели не пересекаются (no pointer aliasing). Это позволяет безопасно кэшировать чтение через read-only data cache (`__ldg`) и переупорядочивать инструкции загрузки.

## 2. Grid-Stride Loop и побитовый интерливинг (`expand_bits_gpu`)

```cpp
const uint32_t idx = blockIdx.x * blockDim.x + threadIdx.x;
const uint32_t stride = blockDim.x * gridDim.x;

for (uint32_t i = idx; i < count; i += stride) {
    ...
    out_codes[i] = (xx << 2) | (yy << 1) | zz;
}
```

* **Масштабируемость через Grid-Stride Loop:** Ядро отвязано от жёсткого размера входного массива. Запускается фиксированная сетка блоков (до `1024` блоков по `256` потоков), оптимально загружающая потоковые мультипроцессоры (SM) GPU независимо от масштаба сцены (будь то \(10^4\) или \(10^7\) примитивов).
* **Отображение 3D \(\to\) 1D за \(O(1)\) без ветвлений:** Каждая нормализованная координата квантуется в 10-битное целое (\([0..1023]\), дискретизация пространства \(1024^3\)). Функция `expand_bits_gpu` раздвигает биты каждого числа на 2 позиции с помощью битовых масок (`0xFF0000FF`, `0x0F00F00F`, `0xC30C30C3`, `0x49249249`) и объединяет их в 30-битный ключ `uint32_t` (**Z-order curve / кривая Лебега**).
* **Применение в 3D-симуляторе:** Кривая Мортона сохраняет пространственную локальность в линейной памяти. Отсортировав массив кодов за один проход параллельной сортировки (`thrust::sort_by_key` / radix sort), можно за логарифмическое время строить линейное дерево ограничивающих объёмов (**LBVH**) для мгновенного отсечения непересекающихся примитивов.

## 3. Аппаратный замер времени (`cudaEvent`) и архитектура продакшена

```cpp
cudaEventRecord(start);
compute_morton_kernel<<<blocks, threads>>>(d_xs, d_ys, d_zs, d_codes, count);
cudaEventRecord(stop);
cudaEventSynchronize(stop);

float kernel_ms = 0.0f;
cudaEventElapsedTime(&kernel_ms, start, stop);
```

* **Корректное профилирование GPU:** Запуск CUDA-ядра (`<<<...>>>`) асинхронен относительно CPU, поэтому замер через `std::chrono` без барьера синхронизации измерит только время постановки задачи в очередь. Использование событий в CUDA stream (`cudaEventRecord` + `cudaEventSynchronize`) фиксирует чистое время исполнения на вычислительных блоках GPU.
* **Результаты замеров (NVIDIA T4, \(1\,000\,000\) примитивов):**
  * **CPU (векторизованный NumPy):** `37.23 ms`
  * **GPU (CUDA Kernel):** `0.201 ms` (**ускорение в 185.2 раза**)
* **Устранение узкого места шины PCIe в реальном симуляторе:** В изолированном бенчмарке данные копируются по PCIe на каждый запуск. В продакшн-симуляторе статическая CAD-геометрия сцены (миллионы треугольников заготовки и оснастки) загружается в видеопамять (`cudaMemcpyHostToDevice`) **один раз при открытии проекта**. На каждом тике симуляции с хоста на GPU передаются только текущие углы суставов манипулятора (6 чисел `float` = **24 байта**), а прямая кинематика звеньев и поиск коллизий полностью выполняются внутри VRAM.

## 4. Интеграция с Python (`ctypes`) и верификация

```python
lib = ctypes.CDLL("./libmorton_gpu.so")
lib.benchmark_morton_gpu.argtypes = [
    np.ctypeslib.ndpointer(dtype=np.float32, flags="C_CONTIGUOUS"),
    ...
]
assert np.array_equal(gpu_codes, cpu_codes)
```

* **Zero-copy передача буферов:** Скомпилированная разделяемая библиотека `libmorton_gpu.so` (`-O3 -arch=sm_75 -fPIC`) получает прямые указатели на непрерывную память массивов NumPy (`C_CONTIGUOUS`) без промежуточной сериализации на стороне Python.
* **Детерминированный Quality Gate:** Выходной массив кодов с GPU сверяется побитово (`assert np.array_equal`) с эталонной реализацией на CPU.
